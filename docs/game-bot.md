# P0：并行启动正式美术生产

## A1 · 三张正式 Style Frame

这是美术仓接下来最优先的工作，应该与 M1 人工试玩并行，而不是等待全部玩法开发完成。

| Style Frame | 验证内容                         |
| ----------- | ---------------------------- |
| **凡尘山村**    | 山水、建筑、生活痕迹、材质、人物比例和基础光照      |
| **筑基对结丹**   | 结丹以本命法宝和多线控制压制筑基，而不是单纯增加爆炸规模 |
| **结丹对元婴**   | 元婴夺取战场控制权，使结丹法宝停滞、偏转或失去锁定    |

完成标准：

* 无生成文字、无正式 UI；
* 三张图能明显看出属于同一项目；
* 不看境界标签也能判断力量层级；
* 构图能够实际转化为固定斜俯视 3D 游戏画面；
* 通过现有美术验收清单。

> A1 未通过前，不应开始批量建模。

# P1：建立第一套正式运行时资产

## A2 · Character Kit

首个角色套件建议包含：

```text
主角基础体型
凡人阶段服装
炼气阶段服装增量
筑基阶段服装增量
共享人形骨架
飞剑挂点
符袋挂点
药瓶挂点
护体器物挂点
一名炼气敌人
一名筑基敌人
```

完成标准：

* 角色维持 `7.0～7.5` 头身；
* 固定正交镜头下能辨别朝向和武器方向；
* 境界变化不依赖整套金光华服；
* 玩家、炼气敌人、筑基敌人轮廓差异明确；
* 可以替换当前 Demo 中的胶囊占位体。

## A3 · Environment Kit

围绕「青岚谷」建立第一套模块化场景：

```text
岩石
土路
溪流
竹木
灌木
石阶
残墙
木构小亭
阵眼
洞府入口
石材 Trim Sheet
木材 Trim Sheet
地表材质
雨后气氛
薄雾气氛
晨光气氛
```

完成标准：

* 同一套资产可以组成至少三个不同战斗区域；
* 角色、飞剑轨迹和敌人预警不会被环境遮挡；
* 不依赖大量独占贴图和独占材质；
* 能替换现有平面、石块和石柱占位场景。

## A4 · Combat VFX Kit

第一批正式特效应只覆盖 Demo 已经存在的能力：

| 特效       | 用途        |
| -------- | --------- |
| 御剑普通攻击轨迹 | 三段普通攻击    |
| 青锋剑诀     | 远距离技能     |
| 普通命中     | 命中无护体目标   |
| 护体命中     | 攻击被护体灵光吸收 |
| 破防反馈     | 护体或阵眼被打破  |
| 身法残影     | 闪避位移      |
| 筑基护体     | 大境界压制     |
| 锁灵阵眼     | 任务目标      |
| 遁光阵      | 撤离目标      |

完成标准：

* 不看数值也能识别命中、护体和破防；
* 筑基护体明显强于炼气护体，但不表现成天地异象；
* 特效不遮挡敌人前摇和危险边界；
* 目标平台达到稳定的当前 60 FPS 基线。

## A5 · UI Kit

第一套 UI 不需要覆盖完整游戏，只需要形成可复用组件：

```text
气血条
灵力条
技能状态
冷却状态
Buff / Debuff
神识威胁等级
任务目标
对话框
物品卡
功法卡
境界突破标题
章节标题
```

完成标准：

* 1080p 下清晰可读；
* 中文全部由正式字体渲染；
* 有完整字体授权记录；
* 不常驻显示精确战力数字；
* 可用于后续坊市、任务、功法和突破系统。

# P1：M2 · Realm Slice

M2 是第一个真正体现“修仙成长”的完整切片，范围为：

> **炼气四层 → 筑基初期**

## M2.1 · 坊市与情报

主要任务：

```text
进入坊市
获取目标情报
查看敌人可能境界
查看区域危险程度
购买丹药、符箓和遁符
选择携带物
```

完成标准：

* 情报能够改变玩家准备方案；
* 玩家不知道所有敌人的精确数值；
* 神识只能给出合理范围或威胁判断；
* 消耗品不是单纯回血药。

## M2.2 · 持久物品与准备系统

实现最小版本：

```text
背包
快捷消耗品
丹药
攻击符箓
护体符箓
遁符
任务物品
灵石
```

不在这个阶段实现：

```text
复杂随机词条
完整炼丹模拟
完整炼器模拟
装备耐久
数百种材料
```

## M2.3 · 山谷任务

将当前「青岚谷脱身」扩展为正式任务：

```text
接受任务
→ 进入山谷
→ 对抗妖兽
→ 对抗炼气邪修
→ 获取目标材料
→ 筑基修士出现
→ 破阵撤离
→ 返回坊市或宗门
```

当前 Demo 已经提前验证了“同境界战斗、筑基压制、破阵和撤离”部分，M2 需要补齐任务前后的持久流程。

## M2.4 · 筑基突破

突破不能只是点击按钮增加属性，需要包含：

```text
修为达到瓶颈
准备筑基材料
选择突破地点
服用筑基丹或替代资源
维持经脉稳定
处理灵力失控
完成突破
```

突破后必须立即产生规则质变：

* 真元护体；
* 神识探查增强；
* 灵力上限和恢复方式变化；
* 可同时控制更多法器；
* 对炼气敌人的天然压制；
* 解锁过去无法进入或无法安全通过的区域。

## M2.5 · 筑基后返场验证

让玩家返回旧区域，对比突破前后：

```text
原炼气敌人攻击难以破开护体
原高风险妖兽变为普通威胁
神识范围扩大
部分环境障碍可以直接通过
NPC 称谓和任务权限改变
```

M2 的完成标准是战斗、准备、逃生和突破形成完整闭环，并让玩家通过玩法本身理解大境界差距。

# P2：M3 · Vertical Slice

这是决定项目是否进入正式量产的关键里程碑。

## 内容范围

制作一段 **20～30 分钟、接近最终品质**的完整内容：

```text
一个宗门小场景
一个坊市
一个野外区域
一段完整主任务
三种普通敌人
一个精英敌人
一个章节 Boss
一次完整突破
基础存档
键鼠与手柄
正式角色、场景、动画、VFX 和音频
正式 HUD、对话、物品和功法界面
```

同时加入一次章节级的：

> **筑基与结丹力量差距展示**

这里不要求玩家正面击杀结丹修士，而应通过法宝控制、战场封锁、剧情保护、阵法限制或撤离目标建立压迫感。

## 完成标准

* 从宗门或坊市开始，到任务结束可以完整运行；
* 无开发者解释也能理解基本流程；
* 正式资产生产成本可以被测量；
* 存档、任务、战斗、突破和 UI 能共同工作；
* 外部玩家愿意继续体验后续内容；
* 经过一次完整性能和兼容性检查；
* 只有 M3 通过后，才开始大规模生产角色、地图、敌人和剧情。
