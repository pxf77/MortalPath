# 美术资产生产规格 v0.1

## 1. 目标平台与基准

- 引擎：Godot 4.3+；
- 渲染：3D、绘画化 PBR、固定正交斜俯视；
- 首要平台：Windows PC；
- 基准分辨率：`1920 × 1080`；
- 基准帧率：`60 FPS`；
- 当前阶段：M1 Combat Proof 至 M3 Vertical Slice；
- 原则：先保证战斗可读性、稳定性能和量产效率，再增加近景细节。

数值为首版生产预算，不是永久上限。任何超预算资产必须说明它在固定镜头下带来的可见收益。

## 2. 目录约定

```text
assets/
├── art-guides/                  # 美术基线与参考板
├── characters/
│   ├── player/
│   ├── npc/
│   └── enemies/
├── environments/
│   ├── shared/
│   ├── village/
│   ├── sect/
│   ├── market/
│   └── realm_slice_valley/
├── props/
├── weapons/
├── vfx/
├── ui/
└── audio/
```

命名规则：

- 文件和目录统一使用小写英文 `snake_case`；
- 资产名称包含类型和语义，例如 `chr_player_male_a.glb`、`vfx_sword_qi_hit.tres`；
- 不在文件名中使用版本副本式命名，如 `final_final_2`；
- 源文件与引擎导出文件分离，仓库中优先保存可复现、可导入的轻量产物；
- 大型源文件和高分辨率贴图进入正式量产前再统一确定 Git LFS 策略。

## 3. 角色模型

### 3.1 三角面预算

| 类型 | LOD0 建议范围 |
|---|---:|
| 玩家主角 | 35k～55k |
| 章节 Boss / 核心 NPC | 40k～70k |
| 普通人形敌人 | 18k～35k |
| 普通妖兽 | 15k～40k |
| 远景或群众角色 | 8k～18k |
| 常规武器 / 法器 | 3k～12k |
| 核心本命法宝 | 8k～20k |

固定镜头下优先把面数用于：

1. 头部和发型大轮廓；
2. 衣摆、袖口和肩部轮廓；
3. 手部、武器和法器；
4. 会影响受光和动画的折面。

不把预算浪费在镜头长期不可见的鞋底、内层布料和微小雕花。

### 3.2 贴图预算

| 类型 | 建议 |
|---|---|
| 玩家 / Boss | 2K 主图集，必要时头部或法宝独立 1K～2K |
| 核心 NPC | 2K 主图集 |
| 普通敌人 | 1K～2K，共享材质优先 |
| 群众角色 | 1K，共享衣物与色相变化 |
| 武器 / 法器 | 1K，核心本命法宝可 2K |

- 推荐 Base Color、Normal、ORM 打包；
- M3 前不默认使用 4K；
- 皮肤、布料、金属、木材和玉石必须有不同粗糙度响应；
- 角色颜色变化通过受控遮罩实现，不直接对整张贴图随机染色。

### 3.3 骨骼与绑定

- 人形角色尽量共享统一基础骨架；
- 角色特有骨骼只用于发束、衣摆、袖口、法器挂点和必要配件；
- 挂点至少包括双手、背部、腰部、头部、胸前、脚底与法器环绕中心；
- 飘带和衣摆优先使用少量骨骼与动画约束，避免重型布料模拟成为基础依赖；
- 战斗碰撞体与视觉网格分离。

## 4. 场景资产

### 4.1 模块化尺寸

- 基础网格以 `1 m` 为单位；
- 建筑常用模块采用 `2 m / 4 m` 倍数；
- 门、台阶、栏杆、檐口和道路宽度保持统一尺度表；
- 每个区域先完成灰盒与可玩路径，再制作装饰变体；
- 模块拼接缝必须在正交镜头下不可见或由结构合理遮挡。

### 4.2 材质策略

- 每个区域优先使用 `1～2` 套 2K Trim Sheet；
- 地表、石墙、木构和屋瓦尽可能共享材质；
- 使用顶点色或遮罩控制青苔、湿润、泥尘和破损；
- 重点地标允许独立材质，但必须说明其叙事和构图作用；
- 透明材质只用于必要的水、烟、薄纱与法术，不用于大面积装饰。

### 4.3 植被

- 植被以成组轮廓和层次为主，不追求每片叶片模拟；
- 近景战斗区域降低高频叶片密度，避免干扰预警；
- 可受技能影响的草、竹叶和灌木使用统一轻量响应方案；
- 树冠与建筑遮挡必须支持淡出、裁切或镜头侧构图避让。

### 4.4 碰撞与导航

- 视觉网格不直接作为复杂碰撞体；
- 建筑、岩石和树木使用简化凸体或组合基础碰撞；
- 战斗场地必须先验证导航、闪避空间和技能范围；
- 装饰物不得制造不可见卡点。

## 5. 材质与渲染

### 5.1 绘画化 PBR

- 保留真实光照和材质差异，但减少高频照片噪声；
- Base Color 以大色块和手绘明暗倾向统一画面；
- Roughness 负责区分材质，不以高饱和颜色替代材质信息；
- Normal 强度受控，远镜头下避免表面闪烁；
- 不采用全角色粗黑描边；
- 可对远景山体、植被轮廓和章节插画使用更明显的墨色边缘或雾化处理。

### 5.2 光照预算

- 常规场景以一个主方向光、环境光和少量局部光为主；
- 普通技能原则上不新增持续动态灯；
- 重要技能可使用一个短时局部灯；
- 同屏重要动态灯数量在 M3 样本中控制在 `2` 个以内；
- 通过材质、发光遮罩、屏幕空间和粒子先完成效果，再考虑额外光源。

### 5.3 后处理

- 色彩分级以区域气候为单位，不使用覆盖全游戏的重滤镜；
- Bloom 只强调符文核心、法宝刃口和高能命中点；
- 雾用于空间层次，不遮挡道路、敌人和危险区；
- 景深只用于过场和菜单，不在常规战斗中持续启用；
- 屏幕震动、色差、径向模糊必须短促且可关闭或降低。

## 6. 动画规格

### 6.1 基础原则

- 玩家移动与闪避由游戏逻辑控制，动画不得造成无法预测的位移；
- 攻击位移使用明确的位移曲线或受控 Root Motion；
- 每个攻击动作必须标记：前摇、有效段、后摇、转向窗口、取消窗口；
- 命中帧、VFX、音效和伤害事件使用同一动作时间基线；
- 高境界通过动作经济性体现，不通过删除玩家所需的危险预警体现。

### 6.2 境界动作差异

| 境界 | 动作倾向 |
|---|---|
| 凡俗 / 炼气 | 全身发力、明显准备、后坐力和回收动作 |
| 筑基 | 动作缩短、重心稳定、可同时御器与移动 |
| 结丹 | 手势和意念控制为主，本命法宝承担大量动作 |
| 元婴 | 动作极少，环境、法宝和空间先于身体响应 |

### 6.3 最小动画集

M1 玩家样本：

```text
idle
locomotion_8_direction_blend
attack_light_1
attack_light_2
attack_light_3
dodge
cast_sword_art
cast_guard
hit_light
hit_heavy
death
```

M3 每类人形敌人至少拥有独立的预警、攻击、受击和死亡节奏，不能只通过倍速复用玩家动作。

## 7. VFX 规格

### 7.1 四层结构

每个战斗特效按需要从以下层级组合：

1. **预警层**：地面范围、法器蓄势、符纹或环境变化；
2. **运动层**：剑气、飞剑、法术轨迹；
3. **命中层**：火花、碎屑、材质闪烁、短时停顿；
4. **残留层**：剑痕、烟尘、余火、灵气消散。

不是每个技能都需要四层。普通攻击应简洁，章节强招才使用完整层级。

### 7.2 透明与屏幕覆盖

- 高透明叠层是例外，不是默认；
- 角色轮廓和敌人预警不能被同色烟雾覆盖；
- 地面法阵中心、边界与安全区必须可区分；
- 普通技能建议控制在 `2` 个主要发射器、`1` 条轨迹和 `1` 个命中反馈以内；
- 境界展示可增加层级，但必须符合 [`realm-visual-hierarchy.md`](realm-visual-hierarchy.md) 的覆盖上限。

### 7.3 五行可读性

- 不仅用颜色区分五行；
- 金使用切面和直线，木使用分枝和生长，水使用带状流动，火使用破碎与上升，土使用层叠和沉降，雷使用分叉与脉冲；
- 低饱和环境中，危险技能的边界必须有亮度和形状差异；
- 需验证常见色觉差异下的可辨识度。

## 8. UI 规格

- 设计基准：`1920 × 1080`，支持比例缩放；
- 正文建议不低于 `18 px`，战斗关键信息不低于 `20 px`；
- 书法字只用于大标题，不承担长段正文；
- 背景纹理不能降低文字对比度；
- 图标必须在 `32 px` 和 `48 px` 下仍可辨识；
- 战斗 HUD 只保留生命、灵力、技能、状态与必要威胁信息；
- 精确威胁指数属于调试信息，正式 UI 不常驻显示；
- 所有中文文字由正式字体渲染，禁止使用生成图片中的文字；
- 字体文件、授权凭证和第三方素材许可证不得随意提交到公开仓库。

## 9. 资产制作流程

```text
需求与用途确认
→ 轮廓 / 灰盒
→ 正交镜头可读性评审
→ 高低模与材质
→ 绑定和动画
→ Godot 导入
→ 战斗场景验证
→ 性能与遮挡检查
→ 美术验收
→ 合入主分支
```

不得在灰盒尚未通过时直接投入完整贴图和特效。

## 10. M1 与 M3 资产范围

### M1 · Combat Proof

- 一个主角灰盒升级版；
- 一个炼气近战敌人；
- 一个筑基护体敌人；
- 一个可读的山谷或庭院试验场；
- 普攻、闪避、剑诀、护体和命中反馈；
- 最小 HUD；
- 不要求正式面部、完整服装变体和大规模环境资产。

### M3 · Vertical Slice

- 一个正式主角；
- 三种普通敌人、一个精英、一个章节 Boss；
- 一个宗门小场景、一个坊市局部、一个野外区域；
- 一套模块化建筑与自然环境组件；
- 炼气、筑基和结丹代表性 VFX；
- 一次境界突破演出；
- 正式战斗 HUD、对话框、物品与功法基础界面；
- 一组章节插画或定格过场样本。
