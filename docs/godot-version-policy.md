# Godot 版本策略

当前唯一受支持的引擎版本：**4.7.2 stable**。游戏仓和美术仓的 `toolchain.lock.json` 固定同一补丁版本、官方发行 URL 及 SHA-256，不使用 `latest`、浮动容器标签或版本矩阵。

## 开发与 CI

- macOS 保留 .NET 编辑器发行版，Linux CI 使用标准发行版；二者都是 4.7.2，当前游戏只使用 GDScript。每个编辑器使用自身发行版对应的 4.7.2 导出模板，不能混装标准版与 .NET 模板。
- 安装：`python3 tools/godot_toolchain.py install --templates`。美术导入测试不需要导出模板，可省略 `--templates`。
- 检查：`python3 tools/godot_toolchain.py check --templates`。可通过 `GODOT_BIN` 指定路径，但错误版本立即失败，不回退到其他编辑器。
- 安装器仅下载锁定的官方包，先校验哈希再解压；不覆盖已有非受管文件。macOS 通过真实 App 可执行文件路径启动，避免 .NET 配套库定位错误。
- 本机 Godot 安装于 `/Applications/Godot_mono.app`；项目安装器默认使用忽略提交的 `.tools/godot/`，不修改其他工程的版本。
- 游戏使用 `bash scripts/godot.sh --editor` 打开编辑器；该入口检查精确版本，并在本机已有用户级 .NET SDK 时为当前进程设置正确的 `DOTNET_ROOT`。游戏启动时也检查版本锁，导出包包含该锁。
- 冷导入使用官方 `--import` 命令等待资源导入完成，不使用首帧即退出的 `--editor --quit`。所有引擎错误、脚本错误和资源泄漏均使验证失败。

## 日常验收

只验证 4.7.2，不再日常运行 4.3，也不保留 4.3 dummy 渲染器错误豁免。旧版记录仅作为历史证据。

固定一个版本不等于只跑一种测试。每次相关变更仍检查：

1. 游戏规则、场景流程、输入、反馈/音频、三轮正常输入通关。
2. 真实图形模式反馈、默认/减弱动态/静音三轮录像；主观手感另行人工签收。
3. 匹配模板的 Linux/macOS release 导出，以及宿主平台导出包独立启动。
4. 美术单元测试、源资产导出、预览、预算/清单、Godot 导入实例化和确定性打包；音效另外校验来源哈希与成品。
5. GitHub Actions 中的 Linux 检查。macOS 本地回归不能替代 Linux 的实际 CI 结果。

macOS 验收包使用本地 ad-hoc 签名，不代表已完成 Developer ID 签名、公证或商店发布。未验证的平台不宣称受支持。

## 后续升级

升级是一项独立变更：同时更新两仓锁文件和官方包哈希，安装对应模板，隔离旧导入缓存，执行上述完整回归并审查证据。通过后才调整日常基线；不因新版本发布自动升级，也不默认长期维护旧引擎测试矩阵。
